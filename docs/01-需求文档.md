# social-proxy-agent · 需求文档（PRD）

- 版本：v1.0（2026-10-14）
- 工作模式：创造模式（文档先行 + Phase→Task 闭环）
- 状态：开工

## 1. 背景与目标

需要一个开箱即用的 **HTTP Agent 服务骨架**：以 Koa 3 暴露 API，以 LangGraph 编排 LLM Agent（工具调用 + 多轮会话 + 流式输出），作为后续各类 agent 服务（客服、自动化任务、内部工具）的基座与模板。

一期目标：单机可跑、测试全绿、零外网可测；配好 `OPENAI_API_KEY` 后即可对接任意 OpenAI 兼容模型（OpenAI / DeepSeek / 本地 vLLM 等）。

## 2. 范围

### 本期做（In）

- Koa 3 HTTP 服务：配置校验、统一错误、请求日志、优雅退出、健康检查
- LangGraph ReAct Agent：`calculator` / `current_time` 两个示例工具
- 会话：`threadId` 多轮记忆；内存 checkpointer（Phase 3 评估 SQLite 持久化）
- 流式：SSE 逐 token 输出
- 工程化：TS strict / biome / vitest / 构建产物（`dist/`）

### 本期不做（Out）

- Web UI、鉴权与多租户、RAG / 向量库、人工介入（interrupt / HITL）、多 agent 协作、Docker / CI、监控埋点

## 3. 用户故事

| 编号 | 角色 | 故事 | 优先级 |
|---|---|---|---|
| US1 | 调用方 | POST 一条消息，同步拿到 agent 回复 | P0 |
| US2 | 调用方 | 带同一 `threadId` 多轮对话，自动携带历史 | P0 |
| US3 | 调用方 | 以 SSE 逐段接收输出 | P1 |
| US4 | 运维 | `GET /health` 获取存活状态 | P0 |
| US5 | 开发者 | clone + 装依赖 + `.env` 即可启动；`pnpm test` 离线全绿 | P0 |

## 4. 功能需求

| 编号 | 需求 | 验收要点 |
|---|---|---|
| F1 | 健康检查 `GET /health` | 200，返回 `{status:"ok", uptime, version}` |
| F2 | 同步对话 `POST /agent/chat` | 入参 zod 校验（422 带 details）；返回 `{threadId, reply}`；不传 `threadId` 自动生成 |
| F3 | 流式对话 `POST /agent/chat/stream` | SSE 帧：`message.delta` / `message.done` / `error`；异常时正确收尾不断连悬挂 |
| F4 | 会话历史 `GET /agent/threads/:threadId` | 返回该会话 user/assistant 消息列表；未知 id 404 |
| F5 | 配置模块 `src/config.ts` | env 经 zod 校验；缺失 / 非法 fail-fast，错误信息可读 |
| F6 | 工具集 | `calculator`（四则运算，禁用 `eval`）、`current_time`（IANA 时区） |

## 5. 非功能需求

- **技术**：TypeScript strict；Node ≥ 22；pnpm；ESM（NodeNext）
- **测试**：vitest；覆盖核心逻辑 + 边界；**零真实 API Key、零外网**（FakeChatModel）；SSE 走真实 HTTP 集成测
- **安全**：密钥仅经环境变量注入；不进日志 / 仓库（`.env` 被 gitignore）
- **稳定性**：SIGTERM / SIGINT 优雅退出；错误统一信封 `{error:{code,message,details?}}`
- **可维护**：避免过度抽象；文件按职责分包

## 6. 总验收

1. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` 全绿
2. 配置真实 key 手工冒烟：一问一答 ✓、流式打印 ✓、同 `threadId` 二轮带上下文 ✓
3. 工程规范：每 Task 单 commit（Conventional Commits）
