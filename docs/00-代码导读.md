# 代码导读 —— 如何读懂这个项目

> 目标读者：想通过一个**真实可运行**的小项目学习「HTTP 服务 + LLM Agent」工程实践的开发者。
> 用法建议：**先跑起来 → 按「阅读路线」逐站读源码 → 对照每个文件旁的测试 → 最后做「动手练习」**。
> 源码中的所有教学注释与本导读互相引用，读到不明白处可直接搜注释里的关键词。

## 0. 先跑起来（建立直觉）

```bash
pnpm install
OPENAI_API_KEY=sk-dummy pnpm dev     # 没有 key 也能启动，只是对话接口会报 502
pnpm test                            # 79 个测试全离线，不需要任何 key
```

用 curl 发一轮对话（有真实 key 时），观察 `POST /agent/chat` 返回什么、SSE 接口的逐段输出长什么样 —— 先知道「它做什么」，再读「它怎么做」。完整冒烟步骤见 [技术文档 §10](02-技术文档.md)。

## 1. 一分钟系统全景

```
HTTP 请求
  └─ Koa 中间件链（app.ts 装配）
       logger（记日志）→ error（统一错误信封）→ bodyparser（解析 JSON）→ router
         └─ routes/：校验入参（zod）→ 调用 Agent
              └─ agent/graph.ts：LangGraph 状态图
                   ├─ model 节点（调 LLM）
                   ├─ tools 节点（执行工具）← 二者循环直到模型不再要工具
                   └─ checkpointer（SQLite/内存）：按 thread_id 记住多轮会话
```

两条对话链路：`/agent/chat`（一次调用拿完整回复）与 `/agent/chat/stream`（SSE 逐 token 推给客户端）。两者共用同一张图和同一套会话存储。

## 3. 核心概念速览（初学必读）

- **Koa 与中间件洋葱模型**：`app.use(mw)` 按顺序包成洋葱，每个中间件 `await next()` 进内层、回来再执行剩下的代码。错误从内层向外冒泡，所以「logger 在外层」能既记成功也记失败。
- **zod**：运行时校验库。schema 既是校验规则也是类型来源（`z.infer`）。本项目用它做两件事：env 校验（启动 fail-fast）与请求体校验（失败 → 422 + details）。
- **LangGraph StateGraph**：把 Agent 逻辑写成「状态机图」——**状态**是一份数据（这里主要是 messages 数组），**节点**是函数（读状态、返回局部更新），**边**决定下一步去哪；条件边按函数返回值路由。图式写法的好处：循环（工具调用）与中断恢复被框架统一处理。
- **ReAct 工具调用循环**：模型被 `bindTools` 告知工具 schema → 需要时返回 `tool_calls` → `ToolNode` 执行工具、把结果作为 ToolMessage 追加 → 再问模型 → 直到模型不再要工具，输出最终文本。`src/agent/graph.ts` 就是这个循环的最小实现。
- **checkpointer / thread_id**：每一步图状态按 `thread_id` 存快照。新一轮 `invoke` 只用传新消息，历史自动从快照恢复 —— 这就是「多轮会话」的实现方式。
- **SSE（Server-Sent Events）**：一条长连接上的文本协议，帧格式 `event: xxx\ndata: json\n\n`；适合服务器单向推送（LLM 逐 token 输出）。
- **stream-events 协议（本项目的关键选择）**：LangGraph 的经典 `streamMode:"messages"` 在 1.x 对本项目这类自定义模型只回**聚合后的最终消息**；逐 token 必须让自定义 callback handler 声明 `lc_prefer_chat_model_stream_events = true` 并实现 `handleChatModelStreamEvent`，从 `content-block-delta`（`text-delta`）里取增量。代码在 `src/agent/streaming.ts`，实测记录见 [技术文档 §5](02-技术文档.md)。
- **依赖注入与可测试性**：全项目没有「模块级单例」——config、model、graph、router、log 都从参数传入（`createApp({log, routes})`、`createAgentGraph({model, checkpointer})`）。测试因此可以注入 FakeChatModel 与静音日志，而不碰真实环境。

## 4. 一次请求的完整旅程（走读）

以 `POST /agent/chat {"message":"1+2*3 等于几"}` 为例：

1. **Koa 中间件链**（`src/app.ts`）：logger 记开始时间 → error 挂好兜底 → bodyparser 把 JSON 解析成 `ctx.request.body`。
2. **路由**（`src/routes/agent.ts`）：`chatRequestSchema.parse(body)` —— 校验失败在这里抛 `ZodError`（最终变 422）；通过后取/生成 `threadId`。
3. **invokeAgent**：调 `graph.invoke({messages:[{role:'user',content:...}]}, {configurable:{thread_id}})`。
4. **图内循环**（`src/agent/graph.ts`）：checkpointer 按 thread 恢复历史 → model 节点调 LLM（模型要求调 `calculator`）→ 条件边路由到 tools 节点（求值得 `7`，以 ToolMessage 追加）→ 回 model 节点 → 模型给出最终文本 → 条件边 `END`。
5. **回到路由**：`lastAiReply()` 取最后一条有文本的 AI 消息 → `ctx.body = {threadId, reply}`。
6. **出门**：logger 记录状态码与耗时；客户端拿到 JSON。

**SSE 版（`/agent/chat/stream`）差异在第 3~5 步**：路由先把响应头切成 `text/event-stream`（`ctx.respond=false` 接管原始 `res`），再给图挂上 `TokenStreamHandler`（自定义 callback）→ 模型每吐一个 token，core 回调 `handleChatModelStreamEvent` → 路由立刻写出 `event: message.delta` → 图跑完后补 `event: message.done`（reply 取 handler 累积的最终段）→ `res.end()`。

## 6. 三个必读「坑」（代码注释与文档里都有对应）

1. **Koa 隐式 404 上赋 `ctx.body` 会变 200**：未匹配路由时 status 是「默认 404」（非显式），直接赋 body 会触发 setter 把状态重置为 200。所以 `src/middleware/error.ts` 兜底时先 `ctx.status = status` 再赋值。详见 `30-Resources/troubleshooting/koa-server-gotchas.md`（个人知识库）。
2. **classic `streamMode:"messages"` 只回聚合消息**：细节与替代方案见 §3「stream-events 协议」；实现前做过探针实测，结论沉淀在知识库 `langgraph-js-streaming.md`。
3. **pnpm 10 默认拦截原生构建**：`better-sqlite3` 的安装脚本被忽略会导致运行时报错；解法是在 `package.json` 声明 `pnpm.onlyBuiltDependencies`。`src/agent/checkpoint.ts` 注释有说明。

## 7. 动手练习（从易到难）

1. **加一个工具**：给 `src/agent/tools.ts` 加 `reverse_text`（反转字符串），补测试，重启后让模型调用它。
2. **加一个接口**：`DELETE /agent/threads/:threadId`（提示：checkpointer 的 `deleteThread`，并补集成测试）。
3. **换模型**：`.env` 改成 DeepSeek（`OPENAI_BASE_URL=https://api.deepseek.com/v1`、`OPENAI_MODEL=deepseek-chat`）验证问答与流式。
4. **读图**：把 `graph.ts` 的 `toolsCondition` 换成自定义路由函数，加入「连续 3 次工具调用后强制收束」规则。
5. **观察存储**：启动后 `sqlite3 data/agent.sqlite '.tables'`，找出 checkpoint 表，理解快照怎么存。
6. **进阶**：给图加 `interrupt`（人工确认工具调用）——LangGraph 的 Human-in-the-loop 入口。
