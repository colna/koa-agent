## 2. 架构分层

```
HTTP 请求
  └─ Koa 中间件链：error → logger → bodyparser → router
       └─ routes/（health、agent）
            └─ agent/（graph：model + tools + checkpointer）
                 └─ 外部 LLM（OpenAI 兼容 API）
```

- **app 与 server 分离**：`createApp(deps)` 纯装配、可注入（测试用 FakeChatModel）；`index.ts` 负责进程生命周期。
- **依赖注入**：路由/图通过 factory 接收 config 与模型依赖，测试不读真实 env。

## 4. API 设计

### 4.1 通用约定

- 请求 / 响应：JSON（UTF-8）
- 统一错误信封：

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "请求体不合法", "details": [] } }
```

| HTTP | code | 场景 |
|---|---|---|
| 404 | `NOT_FOUND` | 未知路由 / 未知 thread |
| 422 | `VALIDATION_ERROR` | zod 校验失败（`details` 为 issue 列表） |
| 502 | `AGENT_ERROR` | 上游模型 / agent 运行失败 |
| 500 | `INTERNAL` | 未预期异常 |

### 4.2 `GET /health`

```json
{ "status": "ok", "uptime": 12.34, "version": "0.1.0" }
```

### 4.3 `POST /agent/chat`

请求：

```json
{ "message": "帮我算 1+2*3", "threadId": "可选，缺省自动生成" }
```

- `message`：string，1–4000 字符（trim 后非空）
- `threadId`：`^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`

响应 200：

```json
{ "threadId": "t_abc123", "reply": "1+2*3 = 7" }
```

### 4.4 `POST /agent/chat/stream`

请求同 4.3。响应 `Content-Type: text/event-stream; charset=utf-8`，另设 `Cache-Control: no-cache`、`X-Accel-Buffering: no`。

SSE 帧（`data` 均为 JSON 单行）：

```
event: message.delta
data: {"text":"1+2*3"}

event: message.delta
data: {"text":" = 7"}

event: message.done
data: {"threadId":"t_abc123","reply":"1+2*3 = 7"}
```

- 运行中异常 → `event: error` + `data: {"code":"AGENT_ERROR","message":"..."}`，随后结束
- 思考过程（2026-10-15 增）：`event: reasoning.delta` + `data: {"text":"…"}` —— 模型 reasoning 流的逐段增量（stream-events 的 `reasoning-delta`），前端以**浅色过程样式**展示，不混入正文
- 图表（2026-10-15 增）：`event: chart` + `data: {"spec":{kind,title,categories,series,unit?}}` —— render_chart 工具产出的完整规格（从 ToolMessage **完整内容**解析，不经 tool.end 的 2000 字截断）；前端 ECharts 实时渲染，历史回读经 `toHistory` 还原（§17）
- Token 用量（2026-10-16 增）：`event: usage` + `data: {"inputTokens","outputTokens","totalTokens"}` —— 本轮（含工具轮）模型调用的 usage 累加，收尾前发出；前端显示在气泡底部 + header 会话累计。同步接口在响应体带 `usage` 字段（invoke 前后全量 diff 计算，见 §18）
- 工具过程（2026-10-15 增）：`event: tool.start` + `data: {"calls":[{"name","args"}],"thought?":...}`（模型决定调工具时；`thought` 是模型的过程文本）；`event: tool.end` + `data: {"results":[{"name","result"}]}`（每个 ToolMessage 一条，result 截断 2000 字符）。实现：streamMode:'updates' 下 model 节点更新含 tool_calls → tool.start；tools 节点更新 → tool.end（时序天然正确，无需 events 模式——langgraph 1.5 的 streamMode 无 'events' 枚举）
- 心跳：每 15s 写注释帧 `: ping`
- 实现方式：`ctx.respond = false` + `res.writeHead` 原生写（Koa 3 下 SSE 不经中间件重写）

### 4.5 `GET /agent/threads/:threadId`

响应 200：

```json
{
  "threadId": "t_abc123",
  "messages": [
    { "role": "user", "content": "帮我算 1+2*3" },
    { "role": "assistant", "content": "1+2*3 = 7" }
  ]
}
```

- 从 checkpointer `getState` 读 `messages`，仅映射 user / assistant 的文本消息（tool 消息折叠）；取文本用 `message.text`（兼容流式路径的 content-blocks 数组，自动跳过 reasoning 块——曾因只认字符串 content 导致历史丢失全部助手回复，2026-10-15 修复）；assistant 消息另带 `reasoning` 字段（思考过程，浅色展示；提取自 content 里的 reasoning 块）
- 未知 thread → 404

### 4.6 `POST /agent/threads/:threadId/rewind`

撤回最后一轮问答：删除「最后一条用户消息及其之后的全部消息」（含助手回复与工具轮）。用 LangGraph `RemoveMessage` 按消息 id 写回状态（`updateState`）——被撤回的问答从上下文消失，下一轮从撤回点之前继续。响应 `{ "threadId": "...", "removedCount": 2 }`；无用户消息（未知 thread）→ 404。前端做成「撤回并把问题填回输入框」，见 §14。

### 4.7 `GET /agent/threads`

会话列表（侧栏用），按最后活跃倒序，最多 200 条：

```json
{ "threads": [ { "threadId": "t_abc123", "preview": "查最近30分钟", "messageCount": 10, "updatedAt": "2026-10-15T10:09:09.179Z" } ] }
```

实现：直接查 checkpointer 的 SQLite（`checkpoints` 表每 thread 取最新一条，解析首条用户消息做预览）——`src/agent/threads.ts`，见 §14。

### 4.8 `DELETE /agent/threads/:threadId`

删除会话（连同 checkpoint 记录，不可恢复）。响应 `{ "threadId": "...", "deleted": true }`；未知会话 → 404；非法 id → 422。实现：复用 `SqliteSaver.deleteThread`。

## 5. Agent 设计

- **图**：ReAct，手写 `StateGraph(MessagesAnnotation)`：模型节点 ↔ `ToolNode`（`toolsCondition` 路由）。不采用 prebuilt `createReactAgent`（1.5.0 已 deprecated、迁往 `langchain` 包；手写零额外依赖、完全可控）。
- **工具**：默认无内置业务工具；生产把 SP 工具集注入图（`src/agent/sp-tools.ts`，接口映射见 §12）；测试用最小夹具 echo（`src/testing/echo-tool.ts`）。
- **模型**：`ChatOpenAI({ model: OPENAI_MODEL, apiKey, configuration: { baseURL } })`；`temperature: 0`
- **会话**：`createCheckpointer(AGENT_SQLITE_PATH)`；默认 SQLite（`@langchain/langgraph-checkpoint-sqlite` + better-sqlite3，文件目录自动创建），传 `':memory:'` 退化为 `MemorySaver`。注意：pnpm 10 需在 `package.json` 声明 `pnpm.onlyBuiltDependencies: ["better-sqlite3"]` 放行其原生构建脚本（prebuild-install）。
- **流式**：`graph.stream(input, { configurable: { thread_id }, streamMode: "updates", callbacks: [TokenHandler] })`；`TokenHandler` 设 `lc_prefer_chat_model_stream_events = true` 并实现 `handleChatModelStreamEvent`，从 `content-block-delta`（`text-delta`）取增量 → `message.delta`；结束时从 updates 收 `reply`。
  - 实测结论（2026-10-14，core 1.2.17 / langgraph 1.5.0）：classic `streamMode:"messages"` 对本版本自定义模型只回**聚合后的最终消息**（仅一条，无逐 token）；逐 token 必须走 stream-events 协议；`version:"v3"` 可用但输出协议信封（lifecycle 事件），暂不采用。
- **上下文裁剪（Phase 10）**：model 节点送模型前 `trimHistory(state.messages, AGENT_MAX_INPUT_TOKENS)`——从末尾按粗略 token 预算（长度/3）累计，向前对齐到 human 消息边界（保证 tool_calls 与 ToolMessage 不拆散），单轮超预算时整轮保留。checkpointer 仍存全量，裁剪只影响模型输入。

## 10. 真实模型手工冒烟步骤

1. `cp .env.example .env`，填入 `OPENAI_API_KEY`（对接 DeepSeek 时同时改 `OPENAI_BASE_URL=https://api.deepseek.com/v1`、`OPENAI_MODEL=deepseek-chat`）；`.env` 已被 gitignore，勿提交。

## 11. Monorepo 与 Web（Phase 6）

- **结构**：pnpm workspaces（`apps/*`）；包名 `@social-proxy-agent/server` / `@social-proxy-agent/web`；根脚本 `dev:server` / `dev:web` / `lint` / `typecheck` / `test`（`pnpm -r`）/ `build`（`pnpm -r`）。
- **架构决策：浏览器直连 server（CORS），不隔代理层** —— 依据知识库结论 `sitin-koa-fastify-proxy-streaming`：反代层容易把流式响应整段缓冲。server 的 `corsMiddleware` 对 OPTIONS 预检直接回 204；web 用 `fetch` + ReadableStream 消费 SSE（`EventSource` 只支持 GET，接口是 POST + JSON）。
- **web 技术栈**：Next.js 16（App Router / React Compiler / Turbopack / Tailwind 4 经 `@tailwindcss/turbopack`）；`next typegen` 生成路由类型（`LayoutProps` 等），web 的 typecheck 脚本为 `next typegen && tsc --noEmit`（否则干净检出时类型不存在）。
- **web 配置**：`NEXT_PUBLIC_SERVER_URL`（默认 `http://127.0.0.1:3000`）；web 开发端口 3001。
- **web 测试**：vitest 纯离线 —— SSE 帧解析器单测（含半帧拼接）+ 以本地 mock HTTP 服务做 `streamChat` 集成测。
- **web 侧坑**：相对导入**不能带** `.js` 扩展名（Turbopack 按 bundler 解析，不认 NodeNext 风格；server 侧则相反，必须带）。

## 12. SP Agent（Phase 7）

- **工具 → BFF 接口映射**（均经 minerva，`Authorization: Bearer <sessionToken>`；外层 `{success,data}` 由 `src/sp/client.ts` 解包）：

| 工具 | 接口 |
|---|---|
| `sp_send_signal` | `POST /api/social-proxy/v3/admin/signal/create`（内层 `{success, signal\|error}`；60s 去重 → `signal=null`） |
| `sp_query_script_errors` / `sp_build_error_report` | `GET /api/social-proxy/script/error-logs`（**无聚合接口**，Agent 侧翻页聚合 ≤1 万条） |
| `sp_export_script_errors_csv` | `GET /api/social-proxy/script/error-logs/export`（CSV 流式落盘 `SP_REPORT_DIR`，经 `GET /sp/reports/:name` 下载） |
| `sp_online_overview` | `GET /api/social-proxy/gateway/devices` + `GET /api/sp-online/{summary,timeseries}` |
| `sp_dashboard_query` | `GET /api/social-proxy/v3/dashboard/{overview,creators,funnel,latency,anomalies,trace}` |

- **双环境（2026-10-15 增）**：每个 SP 工具带 `env` 参数（`'dev'` 默认 / `'prod'` 线上）。`createSpTools` 用 `clientFor(env)` 路由到对应 `SpAdminClient`（dev = `SP_ADMIN_BASE_URL`/`SP_ADMIN_TOKEN`；prod = `SP_ADMIN_BASE_URL_PROD`/`SP_ADMIN_TOKEN_PROD`）；线上 token 未配置时返回配置指引文本（不抛错、不阻塞启动），启动日志有 warn。输出/报表/导出文件名均带环境标识（如 `script-errors_prod_20261015_103000.csv`）；system prompt 已教模型「没指明就用 dev，不要把 dev 数据当线上结论」。
- **人工闸门**：`sp_send_signal` 双步确认 —— `confirm=false` 只返回待确认摘要（**零请求**，摘要含目标环境），用户明确同意后再 `confirm=true`（同一 env）真正下发（ADR 见 04-任务进度）。
- **鉴权结论**：自签 JWT（`scripts/make-sp-token.mjs`）对部署环境**不可行**（部署 JWT_SECRET 与仓库文件不一致，dev/prod 均拒签）；实际使用浏览器 sessionToken。
- **报表下载**：`GET /sp/reports/:name`（文件名白名单 + resolve 前缀二次校验，防路径穿越）。

## 13. Skill 接入（sls-logs，Phase 8）

- **模式**：skill 索引进 system prompt（`loadSkills()` 扫 `skills/` 的 SKILL.md frontmatter → `skillsPromptSection()`）+ 可执行能力暴露为工具（渐进式披露，prompt 不塞全文）。
- **新工具 `sls_query_log`**（`src/agent/skills.ts`）：spawn `python3 skills/sls-logs/scripts/sls_query.py`（阿里云 SLS GetLogs，自动分页）。SLS 查询语法要点吸收进工具 description（方括号短语加双引号、`| SELECT` 分析、常用字段），模型免读 SKILL.md 全文。
- **凭证（两种，生产用 OAuth）**：
  - **OAuth（推荐）**：`aliyun configure --mode OAuth --profile <名>`（站点选 INTL；STS 3h 过期，CLI 用 refresh token 自动换发）→ 设 `SLS_ALIYUN_PROFILE`。`loadAliyunOAuthCreds()` 每次查日志前读 `~/.aliyun/config.json` 的 `sts_expiration`，临期（<5min）跑一次 `sts GetCallerIdentity` 触发刷新再重读——工具因此长时间可用。踩坑见知识库 `aliyun-cli-oauth-sls.md`（站点 CN/INTL、region 缺失、`--oauth-site-type` 参数不生效）。
  - **静态文件**：`~/.sls_creds`（bash export 格式，chmod 600）由 `loadSlsCreds()` 解析（保留兼容）。
  - 凭证由 `credsProvider` 在**每次工具调用时**解析（`~/.sls_creds` 模式下支持文件里带 ENDPOINT/PROJECT/LOGSTORE，OAuth 模式用 config 默认值）；缺失不阻塞启动——工具运行时返回配置指引。
- **dev/prod 双环境（2026-10-16 增）**：工具带 `env` 参数（`'dev'` 默认 / `'prod'` 线上）——prod 时用 `SLS_PROJECT_PROD`/`SLS_LOGSTORE_PROD`（默认 `prod-presence-service-log` / `dora-prod-stdout`，与 dev 同账号同 endpoint）覆盖 project/logstore；结果尾部回显 `（环境：dev|prod）`；prompt 已教学区分。背景：SLA 权限本身覆盖两个 project（实测可列出），最初只是没配线上。
- **env**：`SLS_PYTHON_BIN`（默认 `/usr/bin/python3`，Homebrew python 3.13 pyexpat 损坏不可用）、`SLS_ENDPOINT`/`SLS_PROJECT`/`SLS_LOGSTORE`（默认 `us-west-1.log.aliyuncs.com` / `dev-presence-service-log` / `dora-dev-stdout`）、`SLS_PROJECT_PROD`/`SLS_LOGSTORE_PROD`、`SLS_CREDS_PATH`、`SLS_ALIYUN_PROFILE` / `SLS_ALIYUN_CONFIG_PATH` / `SLS_ALIYUN_BIN`。
- **约定**：工具永不抛异常（与 SP 工具集一致）；子进程超时 60s；结果带行数统计（stderr `--- N rows ---`）。
- **验证**：完整链路冒烟通过（2026-10-15）：真实模型 → OAuth STS → 真实 SLS 日志 → 分析与建议 ✓；线上（2026-10-16）：句含「线上」→ 模型自动 env=prod → 返回 prod 真实报错（contact-exchange-api 等）✓。
