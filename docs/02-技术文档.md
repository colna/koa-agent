## 2. 架构分层

```
HTTP 请求
  └─ Koa 中间件链：error → logger → bodyparser → router
       └─ routes/（health、agent）
            └─ agent/（graph：model + tools + checkpointer）
                 └─ 外部 LLM（OpenAI 兼容 API）
```

- **app 与 server 分离**：`createApp(deps)` 纯装配、可注入（测试用 FakeChatModel）；`index.ts` 负责进程生命周期。
- **依赖注入**：路由/图通过 factory 接收 config 与模型依赖，测试不读真实 env。

## 4. API 设计

### 4.1 通用约定

- 请求 / 响应：JSON（UTF-8）
- 统一错误信封：

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "请求体不合法", "details": [] } }
```

| HTTP | code | 场景 |
|---|---|---|
| 404 | `NOT_FOUND` | 未知路由 / 未知 thread |
| 422 | `VALIDATION_ERROR` | zod 校验失败（`details` 为 issue 列表） |
| 502 | `AGENT_ERROR` | 上游模型 / agent 运行失败 |
| 500 | `INTERNAL` | 未预期异常 |

### 4.2 `GET /health`

```json
{ "status": "ok", "uptime": 12.34, "version": "0.1.0" }
```

### 4.3 `POST /agent/chat`

请求：

```json
{ "message": "帮我算 1+2*3", "threadId": "可选，缺省自动生成" }
```

- `message`：string，1–4000 字符（trim 后非空）
- `threadId`：`^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`

响应 200：

```json
{ "threadId": "t_abc123", "reply": "1+2*3 = 7" }
```

### 4.4 `POST /agent/chat/stream`

请求同 4.3。响应 `Content-Type: text/event-stream; charset=utf-8`，另设 `Cache-Control: no-cache`、`X-Accel-Buffering: no`。

SSE 帧（`data` 均为 JSON 单行）：

```
event: message.delta
data: {"text":"1+2*3"}

event: message.delta
data: {"text":" = 7"}

event: message.done
data: {"threadId":"t_abc123","reply":"1+2*3 = 7"}
```

- 运行中异常 → `event: error` + `data: {"code":"AGENT_ERROR","message":"..."}`，随后结束
- 心跳：每 15s 写注释帧 `: ping`
- 实现方式：`ctx.respond = false` + `res.writeHead` 原生写（Koa 3 下 SSE 不经中间件重写）

### 4.5 `GET /agent/threads/:threadId`

响应 200：

```json
{
  "threadId": "t_abc123",
  "messages": [
    { "role": "user", "content": "帮我算 1+2*3" },
    { "role": "assistant", "content": "1+2*3 = 7" }
  ]
}
```

- 从 checkpointer `getState` 读 `messages`，仅映射 user / assistant 的文本消息（tool 消息折叠）
- 未知 thread → 404

## 5. Agent 设计

- **图**：ReAct。优先使用 prebuilt `createReactAgent`（`@langchain/langgraph/prebuilt`，实际导出名以安装包为准）；若 1.5.0 不可用则手写 `StateGraph(MessagesAnnotation)` + 模型节点 ↔ `ToolNode`（`toolsCondition` 路由）。
- **工具**（`src/agent/tools.ts`，均用 zod schema）：
  - `calculator`：仅允许数字 / 四则运算 / 括号 / 小数，自写递归下降或等价安全求值，**禁 `eval`**
  - `current_time`：入参 `timezone`（IANA，默认 `Asia/Shanghai`），非法时区返回错误结果而非抛异常
- **模型**：`ChatOpenAI({ model: OPENAI_MODEL, apiKey, configuration: { baseURL } })`；`temperature: 0`
- **会话**：Phase 2 用内存 checkpointer（`MemorySaver`），`thread_id` 透传；Phase 3 评估 SQLite。
- **流式**：`graph.stream(input, { configurable: { thread_id }, streamMode: "messages" })`，取 `AIMessageChunk.content` 增量 → `message.delta`；结束时从末条消息聚合 `reply`。

## 6. 配置（env）

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `PORT` | 否 | `3000` | 监听端口 |
| `HOST` | 否 | `127.0.0.1` | 监听地址 |
| `NODE_ENV` | 否 | `development` | `development/test/production` |
| `OPENAI_API_KEY` | 是 | — | 启动即校验（fail-fast） |
| `OPENAI_BASE_URL` | 否 | `https://api.openai.com/v1` | OpenAI 兼容端点（如 DeepSeek） |
| `OPENAI_MODEL` | 否 | `gpt-4o-mini` | 模型名 |
| `AGENT_SQLITE_PATH` | 否 | `./data/agent.sqlite` | T3.2 起生效 |

约定：`.env` 仅本地存在、被 gitignore；仓库只提交 `.env.example`；测试不读真实 env（显式注入）。

## 7. 关键约定（继承自知识库）

来源：`colna-memo/memory/30-Resources/troubleshooting/agentscope-ts-sdk-gotchas.md`（Koa 3 + TS 实战结论）：

1. Koa 3 无自动校验 / 文档 → 请求体用 zod `.strict()` 手工校验，失败返 422 `{error, details}`
2. SSE 用 `ctx.respond=false` + `res.writeHead` 原生写
3. 集成测试：`startServer(app)` 随机端口 + 全局 `fetch` 走真实 HTTP
4. 测试静音实验性警告用 `NODE_OPTIONS=--disable-warning=ExperimentalWarning`（仅当 T3.2 用到 `node:sqlite`）

## 8. 测试策略

- **单测**：config（必填/默认/非法）、tools（计算边界、除零、非法时区）、graph（FakeChatModel 驱动工具回合与续话）
- **集成**：真实 HTTP（随机端口 + `fetch`）：health、chat 422/200、SSE 帧解析、threads 404/200
- **离线**：`FakeChatModel extends BaseChatModel`（`@langchain/core`），覆写 `_generate` / `_stream`；支持脚本化回合（先 `tool_calls` 再最终回复）与 `bindTools` 记录
- **禁止**：真实 API Key、真实外网请求进入测试

## 9. 风险与决策点

| 风险 | 预案 |
|---|---|
| LangGraph 1.x prebuilt 导出名变化 | T2.3 实现时以安装包 `exports` 为准；不可用则手写 StateGraph（成本可控） |
| `checkpoint-sqlite` 原生依赖（better-sqlite3）不好装 | T3.2 评估：可用则上；不可用则记录结论降级 MemorySaver，留待决 |
| TS 7.x 生态兼容未知 | 本期锁 ~5.9.3（姊妹项目已验证组合）；升级另开任务 |
| SSE 经反代被缓冲 | 已设 `X-Accel-Buffering: no`；部署层问题本期不展开 |
