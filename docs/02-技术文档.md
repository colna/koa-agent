## 2. 架构分层

```
HTTP 请求
  └─ Koa 中间件链：error → logger → bodyparser → router
       └─ routes/（health、agent）
            └─ agent/（graph：model + tools + checkpointer）
                 └─ 外部 LLM（OpenAI 兼容 API）
```

- **app 与 server 分离**：`createApp(deps)` 纯装配、可注入（测试用 FakeChatModel）；`index.ts` 负责进程生命周期。
- **依赖注入**：路由/图通过 factory 接收 config 与模型依赖，测试不读真实 env。

## 4. API 设计

### 4.1 通用约定

- 请求 / 响应：JSON（UTF-8）
- 统一错误信封：

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "请求体不合法", "details": [] } }
```

| HTTP | code | 场景 |
|---|---|---|
| 404 | `NOT_FOUND` | 未知路由 / 未知 thread |
| 422 | `VALIDATION_ERROR` | zod 校验失败（`details` 为 issue 列表） |
| 502 | `AGENT_ERROR` | 上游模型 / agent 运行失败 |
| 500 | `INTERNAL` | 未预期异常 |

### 4.2 `GET /health`

```json
{ "status": "ok", "uptime": 12.34, "version": "0.1.0" }
```

### 4.3 `POST /agent/chat`

请求：

```json
{ "message": "帮我算 1+2*3", "threadId": "可选，缺省自动生成" }
```

- `message`：string，1–4000 字符（trim 后非空）
- `threadId`：`^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`

响应 200：

```json
{ "threadId": "t_abc123", "reply": "1+2*3 = 7" }
```

### 4.4 `POST /agent/chat/stream`

请求同 4.3。响应 `Content-Type: text/event-stream; charset=utf-8`，另设 `Cache-Control: no-cache`、`X-Accel-Buffering: no`。

SSE 帧（`data` 均为 JSON 单行）：

```
event: message.delta
data: {"text":"1+2*3"}

event: message.delta
data: {"text":" = 7"}

event: message.done
data: {"threadId":"t_abc123","reply":"1+2*3 = 7"}
```

- 运行中异常 → `event: error` + `data: {"code":"AGENT_ERROR","message":"..."}`，随后结束
- 心跳：每 15s 写注释帧 `: ping`
- 实现方式：`ctx.respond = false` + `res.writeHead` 原生写（Koa 3 下 SSE 不经中间件重写）

### 4.5 `GET /agent/threads/:threadId`

响应 200：

```json
{
  "threadId": "t_abc123",
  "messages": [
    { "role": "user", "content": "帮我算 1+2*3" },
    { "role": "assistant", "content": "1+2*3 = 7" }
  ]
}
```

- 从 checkpointer `getState` 读 `messages`，仅映射 user / assistant 的文本消息（tool 消息折叠）
- 未知 thread → 404

## 5. Agent 设计

- **图**：ReAct，手写 `StateGraph(MessagesAnnotation)`：模型节点 ↔ `ToolNode`（`toolsCondition` 路由）。不采用 prebuilt `createReactAgent`（1.5.0 已 deprecated、迁往 `langchain` 包；手写零额外依赖、完全可控）。
- **工具**（`src/agent/tools.ts`，均用 zod schema）：
  - `calculator`：仅允许数字 / 四则运算 / 括号 / 小数，自写递归下降或等价安全求值，**禁 `eval`**
  - `current_time`：入参 `timezone`（IANA，默认 `Asia/Shanghai`），非法时区返回错误结果而非抛异常
- **模型**：`ChatOpenAI({ model: OPENAI_MODEL, apiKey, configuration: { baseURL } })`；`temperature: 0`
- **会话**：`createCheckpointer(AGENT_SQLITE_PATH)`；默认 SQLite（`@langchain/langgraph-checkpoint-sqlite` + better-sqlite3，文件目录自动创建），传 `':memory:'` 退化为 `MemorySaver`。注意：pnpm 10 需在 `package.json` 声明 `pnpm.onlyBuiltDependencies: ["better-sqlite3"]` 放行其原生构建脚本（prebuild-install）。
- **流式**：`graph.stream(input, { configurable: { thread_id }, streamMode: "updates", callbacks: [TokenHandler] })`；`TokenHandler` 设 `lc_prefer_chat_model_stream_events = true` 并实现 `handleChatModelStreamEvent`，从 `content-block-delta`（`text-delta`）取增量 → `message.delta`；结束时从 updates 收 `reply`。
  - 实测结论（2026-10-14，core 1.2.17 / langgraph 1.5.0）：classic `streamMode:"messages"` 对本版本自定义模型只回**聚合后的最终消息**（仅一条，无逐 token）；逐 token 必须走 stream-events 协议；`version:"v3"` 可用但输出协议信封（lifecycle 事件），暂不采用。

## 6. 配置（env）

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `PORT` | 否 | `3000` | 监听端口 |
| `HOST` | 否 | `127.0.0.1` | 监听地址 |
| `NODE_ENV` | 否 | `development` | `development/test/production` |
| `CORS_ORIGIN` | 否 | `*` | 允许跨域直连的来源；生产建议设为 web 域名 |
| `OPENAI_API_KEY` | 是 | — | 启动即校验（fail-fast） |
| `OPENAI_BASE_URL` | 否 | `https://api.openai.com/v1` | OpenAI 兼容端点（如 DeepSeek） |
| `OPENAI_MODEL` | 否 | `gpt-4o-mini` | 模型名 |
| `AGENT_SQLITE_PATH` | 否 | `./data/agent.sqlite` | T3.2 起生效 |

约定：`.env` 仅本地存在、被 gitignore；仓库只提交 `.env.example`；测试不读真实 env（显式注入）。

## 7. 关键约定（继承自知识库）

来源：`colna-memo/memory/30-Resources/troubleshooting/agentscope-ts-sdk-gotchas.md`（Koa 3 + TS 实战结论）：

1. Koa 3 无自动校验 / 文档 → 请求体用 zod `.strict()` 手工校验，失败返 422 `{error, details}`
2. SSE 用 `ctx.respond=false` + `res.writeHead` 原生写
3. 集成测试：`startServer(app)` 随机端口 + 全局 `fetch` 走真实 HTTP
4. 测试静音实验性警告用 `NODE_OPTIONS=--disable-warning=ExperimentalWarning`（仅当 T3.2 用到 `node:sqlite`）

## 8. 测试策略

- **单测**：config（必填/默认/非法）、tools（计算边界、除零、非法时区）、graph（FakeChatModel 驱动工具回合与续话）
- **集成**：真实 HTTP（随机端口 + `fetch`）：health、chat 422/200、SSE 帧解析、threads 404/200
- **离线**：`FakeChatModel extends BaseChatModel`（`@langchain/core`），覆写 `_generate` 与 `_streamResponseChunks`（脚本化回合：文本按片输出 + `tool_call_chunks` 重建，保证流式路径下工具轮不丢）；`bindTools` 记录绑定工具
- **禁止**：真实 API Key、真实外网请求进入测试

## 9. 风险与决策点

| 风险 | 预案 |
|---|---|
| LangGraph 1.x prebuilt 导出名变化 | T2.3 实现时以安装包 `exports` 为准；不可用则手写 StateGraph（成本可控） |
| `checkpoint-sqlite` 原生依赖（better-sqlite3）不好装 | 已解决（2026-10-14）：pnpm `onlyBuiltDependencies` 显式放行 → prebuild-install 成功；测试验证“新实例续读同 thread”通过 |
| TS 7.x 生态兼容未知 | 本期锁 ~5.9.3（姊妹项目已验证组合）；升级另开任务 |
| SSE 经反代被缓冲 | 已设 `X-Accel-Buffering: no`；部署层问题本期不展开 |

## 10. 真实模型手工冒烟步骤

1. `cp .env.example .env`，填入 `OPENAI_API_KEY`（对接 DeepSeek 时同时改 `OPENAI_BASE_URL=https://api.deepseek.com/v1`、`OPENAI_MODEL=deepseek-chat`）；`.env` 已被 gitignore，勿提交。
2. 启动：开发 `pnpm dev`；生产构建 `pnpm build && node dist/index.js`（默认 `http://127.0.0.1:3000`）。
3. 冒烟命令：
   - 健康：`curl -s http://127.0.0.1:3000/health`
   - 同步对话（会触发工具）：`curl -s -X POST http://127.0.0.1:3000/agent/chat -H 'content-type: application/json' -d '{"message":"帮我算 1+2*3 等于几"}'`
   - 流式（SSE，`-N` 关闭缓冲）：`curl -N -X POST http://127.0.0.1:3000/agent/chat/stream -H 'content-type: application/json' -d '{"message":"讲个 50 字内的小故事","threadId":"t_smoke_0001"}'`
   - 会话历史：`curl -s http://127.0.0.1:3000/agent/threads/t_smoke_0001`
4. 二轮同一 `threadId` 再发一次，确认回复携带上下文；重启进程后历史仍在（SQLite）。
5. 提交前保证：`pnpm lint && pnpm typecheck && pnpm test && pnpm build` 全绿。

## 11. Monorepo 与 Web（Phase 6）

- **结构**：pnpm workspaces（`apps/*`）；包名 `@koa-agent/server` / `@koa-agent/web`；根脚本 `dev:server` / `dev:web` / `lint` / `typecheck` / `test`（`pnpm -r`）/ `build`（`pnpm -r`）。
- **架构决策：浏览器直连 server（CORS），不隔代理层** —— 依据知识库结论 `sitin-koa-fastify-proxy-streaming`：反代层容易把流式响应整段缓冲。server 的 `corsMiddleware` 对 OPTIONS 预检直接回 204；web 用 `fetch` + ReadableStream 消费 SSE（`EventSource` 只支持 GET，接口是 POST + JSON）。
- **web 技术栈**：Next.js 16（App Router / React Compiler / Turbopack / Tailwind 4 经 `@tailwindcss/turbopack`）；`next typegen` 生成路由类型（`LayoutProps` 等），web 的 typecheck 脚本为 `next typegen && tsc --noEmit`（否则干净检出时类型不存在）。
- **web 配置**：`NEXT_PUBLIC_SERVER_URL`（默认 `http://127.0.0.1:3000`）；web 开发端口 3001。
- **web 测试**：vitest 纯离线 —— SSE 帧解析器单测（含半帧拼接）+ 以本地 mock HTTP 服务做 `streamChat` 集成测。
- **web 侧坑**：相对导入**不能带** `.js` 扩展名（Turbopack 按 bundler 解析，不认 NodeNext 风格；server 侧则相反，必须带）。
